# 大麦电脑版不卖演出占比与移动版接口实测调研

- 日期：2026-10-14（北京时间 17:21–17:41）
- 相关：[#8](https://github.com/zbtzbtzbt/theFlash/issues/8)、[#6](https://github.com/zbtzbtzbt/theFlash/issues/6)、[#54](https://github.com/zbtzbtzbt/theFlash/issues/54)、[0001](../decisions/0001-damai-event-data-source.md)、[0014](../decisions/0014-inspection-sample-pool.md)、[0018](../decisions/0018-browser-handoff.md)

## 核心结论摘要

1. **大麦上有多少演出电脑版不卖（`buyBtnStatus == 100`，“该渠道不支持购票”）？**
   - **全品类总体不是多数，但存在显著品类分化**：在本次匿名实测的 **130 场**真实演出样本中，电脑版不卖（`buyBtnStatus == 100`）共 **46 场（35.4%）**，电脑版正常售卖或展示场次的共 **83 场（63.8%）**（另 1 场境外演出状态码为 `90`）。若只看首页 4 大分类模块直接抽样的 **115 场**演出（不含巡演分站扩展），电脑版不卖为 **34 场（29.6%）**，电脑版支持购票的占 **70.4%**。
   - **热门演唱会中电脑版不卖占绝大多数（75.0%～80.0%）**：在详情页细分品类 `guideCat == "演唱会"` 的 **47 场**样本中，**36 场（76.6%）** 为 `buyBtnStatus == 100`（若只看首页推荐位中的 32 场演唱会，**24 场 / 75.0%** 为 `100`；若看 `isHotProject == true` 的 40 场热门演唱会，**32 场 / 80.0%** 为 `100`）。相反，同样出现在首页「演唱会」模块里的 **9 场 `Livehouse` 演出和 1 场 `音乐节` 全部支持电脑版购票（0% 为 `100`）**；`儿童亲子`（0.0%）、`体育比赛`（12.5%）、`话剧歌剧`（25.0%）也以电脑版可售为主。
2. **只在 App 卖的演出（`buyBtnStatus == 100`），不登录能不能在移动版（`m.damai.cn`）拿到场次和票档，要付出什么代价？**
   - **不能。`m.damai.cn`（移动 H5 渠道 `dmChannel=damai@damaih5_h5`）同样不卖，也拿不到场次和票档！**
   - 实测 3 场 `buyBtnStatus == 100` 的演唱会（`1080486727522` 动力火车北京站、`1072691062992` 林忆莲上海站、`1080802118423` 许嵩成都站）在浏览器打开 `https://m.damai.cn/damai/detail/item.html?itemId=<id>`（302 跳转至 `https://m.damai.cn/shows/item.html?itemId=<id>`）：
     - 页面首次请求 `mtop.damai.item.detail.getdetail`（`v=1.0`）先因无令牌下发 `_m_h5_tk=<redacted>` 与 `_m_h5_tk_enc=<redacted>`，随后自动计算 `sign = md5(token + "&" + t + "&" + appKey + "&" + data)` 发起第二次请求并成功返回。
     - **但接口返回的购买状态依然是 `status: "100"`（`text: "该渠道不支持购票"`、`tip: "请到大麦App购买"`、`enable: false`），且 `skuData: null`！** 移动版页面底部按钮同样置灰禁用，页面上只展示汇总演出时间字符串（如 `2026.10.16-10.17`）和价格区间字符串（如 `480-1380`）——这两项汇总字段在电脑版详情页 HTML（`staticDataDefault.itemBase.showTime` 与 `dataDefault.priceRange`）里本来就有，移动版 H5 并未多返回任何场次 `performId` 或票档 `skuList`。
     - 此外，对电脑版可售的演出（如 `1084160409867` Charlie Puth 广州站，`status == 204`），`m.damai.cn` 详情页首屏的 `mtop.damai.item.detail.getdetail` 同样只返回 `skuData: null`；只有点击「立即预订」时才会去调票档子页面接口 `mtop.alibaba.detail.subpage.getdetail`（`v=2.0`），而**未登录点击「立即预订」会立即被重定向到登录页 `https://m.damai.cn/shows/login.html`**。也就是说，即便对于普通在售演出，`m.damai.cn` 在不登录时反而拿不到电脑版 `detail.damai.cn/subpage` 能匿名拿到的场次和票档。
   - **真正拿到 App 专卖演出的场次和票档要付出什么代价**：必须弃用 H5 渠道（`damai@damaih5_h5`），改为逆向大麦原生 App 渠道（`dmChannel=damai@damaiapp_app`）的接口协议，并伪造阿里无线保镖签名（`x-sign` / `x-mini-wua` / `wua` 设备指纹）及携带登录态。这直接违反 [#6](https://github.com/zbtzbtzbt/theFlash/issues/6) 裁决的「不绕过任何风控」原则，且因为网页/H5 渠道被禁止下单，也无法配合 [#54](https://github.com/zbtzbtzbt/theFlash/issues/54)（[0018](../decisions/0018-browser-handoff.md)）在用户浏览器里打开确认页完成辅助抢票。

### 3. 为什么 `m.damai.cn` 也拿不到场次和票档？

从 3 场 `buyBtnStatus == 100` 演出的 `m.damai.cn` 页面及 Redux 状态树（`store.getState().showDetail`）中可以看到：

1. **移动版 H5（`dmChannel: "damai@damaih5_h5"`）同样被归为“不支持购票渠道”**：
   - 以 `1080486727522`（动力火车北京站）、`1072691062992`（林忆莲上海站，10.16–10.17 两场）、`1080802118423`（许嵩成都站，10.23/10.25 两场）为例，`mtop.damai.item.detail.getdetail` 返回给移动版 H5 的购买信息均为：
     ```json
     {
       "baseInfo": {
         "status": "100",
         "text": "该渠道不支持购票",
         "tip": "请到大麦App购买",
         "toast": "",
         "enable": false,
         "style": 1,
         "isChoose": false
       },
       "skuData": null
     }
     ```
   - 页面上只渲染了 `cityServiceInfo.showTime`（如 `"2026.10.16-10.17"`、`"2026.10.23-10.25"`）和 `promotionInfo.price.range`（如 `"380-1280"`、`"480-1380"`、`"318-1618"`），**没有任何单场次 `performId`、各票档名称/价格列表（`skuList`）或各票档余票状态**。
   - 换言之，“该渠道不支持购票（请到大麦App购买）”封禁的是**所有网页/H5 渠道（包含电脑版 `pc@damai_pc` 和移动网页版 `damai@damaih5_h5`）**，而不是只封电脑版、放行 `m.damai.cn`。
2. **即便在移动版上，票档子接口 `mtop.alibaba.detail.subpage.getdetail` 也需要登录且不对 `status == 100` 开放**：
   - 从 `show-h5-next/2026.09.23/item.426b7ecd.js` 与 `1070.65374db9.js` 的逻辑及 `1084160409867`（Charlie Puth 广州站，`status == 204`）的实测可见：
     - `m.damai.cn` 首屏 `mtop.damai.item.detail.getdetail` 即使对 `status == 204` 的在售演出，返回的也是 `skuData: null`；
     - 场次与票档抽屉的数据来自另一个 `mtop` 接口 `mtop.alibaba.detail.subpage.getdetail`（`v=2.0`，参数 `scenario: "itemsku"`）；
     - 点击「立即预订」按钮时，前端先判断 `baseInfo.enable`（`status == 100` 时为 `false`，直接拦截），再执行登录态检查：未登录时直接跳转到 `https://m.damai.cn/shows/login.html?returnUrl=...`（内嵌 `ipassport.damai.cn/mini_login.htm`），根本不会发起 `mtop.alibaba.detail.subpage.getdetail` 请求。
3. **要在真正的大麦 App 渠道拿到场次和票档需要付出什么代价**：
   - 在 `1866.d73a043e.js` 的渠道映射中可以看到，大麦把 H5（`damai@damaih5_h5`）、微信小程序（`damai@weixin_weapp`）、支付宝小程序（`damai@alipay_h5`）与大麦原生 App（`damai@damaiapp_app`）严格区分。
   - 原生 App 专卖演出的数据由客户端专有接口（如 App 端 `mtop.alibaba.damai.detail.getdetail` v1.2，`dmChannel=damai@damaiapp_app`）返回，网关侧不仅校验登录会话，还校验阿里无线保镖（SecurityGuard）生成的设备指纹与请求签名（`x-sign`、`x-mini-wua`、`wua`、`x-umt` 等请求头），无法仅靠 H5 的 `_m_h5_tk` MD5 签名调用。

## 四、对 `0001` 重新考虑条件的判断与对 `#6` 的建议

### 1. [0001](../decisions/0001-damai-event-data-source.md) 的重新考虑条件是否成立？

[0001](../decisions/0001-damai-event-data-source.md) 写明的重新考虑条件是：
> 出现以下证据时应重新考虑：subpage 接口开始要求登录或签名；电脑版不卖的演出成为多数；风控开始拦截详情页。

逐条对照本次实测证据：
1. **`subpage` 接口是否开始要求登录或签名？** **否**。电脑版可售演出的 `detail.damai.cn/subpage` 依然匿名可用、无需 `_m_h5_tk` 签名或登录。
2. **风控是否开始拦截详情页？** **否**。本次按 ≥ 2.3 秒间隔匿名请求 130 场详情页，全部 HTTP 200 正常返回，零次触发滑块或限流。
3. **电脑版不卖的演出是否成为多数？**
   - **全站全品类口径：未成为多数**（130 场样本中占 **35.4%**，115 场首页样本中占 **29.6%**；电脑版可售演出占 **64.6%～70.4%**，其中 `Livehouse`、`儿童亲子`、`体育比赛`、`话剧歌剧` 绝大多数都在电脑版正常售卖）。
   - **大型演唱会（`guideCat == "演唱会"`）口径：已成为多数（75.0%～80.0%）**。
   - **但 [0001](../decisions/0001-damai-event-data-source.md) 不应因此改用 `m.damai.cn`（方案 2 `mtop` H5 接口）**：
     - 当时 [0001](../decisions/0001-damai-event-data-source.md) 把 `mtop` H5 接口列为备选方案 2，隐含的前提是“如果电脑版不卖，也许移动版 `m.damai.cn` 能拿到场次和票档”。
     - 本次实测证明该前提**不成立**：对于 `buyBtnStatus == 100` 的演出，`m.damai.cn` 同样返回 `status: "100"` 和 `skuData: null`；而对于 `204`/`206` 的在售演出，`m.damai.cn` 反而在未登录时不返回票档并强制跳转登录页。因此切换到 `m.damai.cn` 不仅要额外承担 `_m_h5_tk` 签名与更高的风控风险，而且**在功能上是净退步（0 场新增支持，反而丢掉电脑版可售演出的免登录票档查询能力）**。
   - **结论**：**维持 [0001](../decisions/0001-damai-event-data-source.md) 的电脑版数据源决定不变**。

### 2. 给 [#6](https://github.com/zbtzbtzbt/theFlash/issues/6) 第 3 问（“只在 App 上卖的演出要不要支持”）的建议

**建议：不支持只在 App 上卖的演出（`buyBtnStatus == 100`），明确将产品边界聚焦在网页/H5 渠道可售的演出（含全部 Livehouse/音乐节、约 20%～25% 的演唱会，以及绝大多数话剧歌剧、音乐剧、体育赛事、儿童亲子）。**

理由如下：
1. **H5 移动版此路不通，支持 App 专卖意味着必须破解原生 App 风控签名**：
   - `m.damai.cn` 对 `buyBtnStatus == 100` 同样不返回场次和票档。
   - 要获取这类演出的场次、票档与下单入口，唯一路径是逆向大麦 Android/iOS 原生客户端协议并伪造无线保镖签名（`x-sign` / `wua`）。这直接违背 [#6](https://github.com/zbtzbtzbt/theFlash/issues/6) 已经由 owner 裁决并写入 [`docs/code-standards.md`](../code-standards.md#owner-的决定) 的安全规则（**“程序不提交订单，不绕过任何风控”**），且极易触发账号封禁和法律风险。
2. **与 [#6](https://github.com/zbtzbtzbt/theFlash/issues/6) 裁决的 A 方案（浏览器辅助抢票，[#54](https://github.com/zbtzbtzbt/theFlash/issues/54) / [0018](../decisions/0018-browser-handoff.md)）闭环矛盾**：
   - A 方案的核心是在开售或回流有票那一刻，在用户的浏览器里打开已选好场次和票档的确认页（`h5-ultron-buy/index.html`）或选座页（`select-seat-biz/kylin.html`），由人点“提交订单”。
   - 而 App 专卖演出在服务端拒绝网页/H5 渠道交易（`该渠道不支持购票，请到大麦App购买`），即便拿到 `skuId` 无法在浏览器端完成下单交接。
3. **可在现有电脑版数据源内顺手改善的体验（无需新数据源）**：
   - 虽然电脑版拿不到 `buyBtnStatus == 100` 演出的单场次 `performId` 和单票档 `skuId`，但电脑版详情页 HTML 已经自带了 `staticDataDefault.itemBase.showTime`（演出时间汇总）、`dataDefault.priceRange`（价格区间）、`dataDefault.sellStartTime`（开售时间）和 `staticDataDefault.tourProjects`（巡演其他城市分站——如本次发现同一巡演中部分分站如动力火车哈尔滨站、Charlie Puth 广州/武汉站、威神V 广州站支持电脑版购票）。后续可在不发任何额外请求的前提下，在 `theflash event` 对 `100` 状态的提示里展示这几项已有信息。
