# 0001. 演出信息从大麦电脑版详情页和它的票档接口获取

- 状态：采用
- 日期：2026-10-14
- 相关：#1

## 背景

#1 要求给一个大麦演出链接，列出演出名称、城市、场馆、场次、票档价格和状态，以及未开售时的开售时间。约束：不登录、不下单，遇到风控就停下。

2026-10-14 用浏览器（computer use）和匿名 `curl` 观察了 28 个首页演出和 20 个巡演分站，结论如下：

- `https://detail.damai.cn/item.htm?id=<演出ID>` 匿名请求就返回完整 HTML。页面里有两个隐藏的 `div`，内容是 JSON：
  - `staticDataDefault`：演出名称、城市、场馆。
  - `dataDefault`：购买按钮状态、开售时间，以及 `performBases`（场次列表，每个场次有 `performId`）。
- 页面再用 JSONP 调 `https://detail.damai.cn/subpage?...&scenario=itemsku&dataType=2&dataId=<performId>` 拿某个场次的票档（`perform.skuList`）。不需要登录、签名或 cookie。不带 `dataType=2` 时，接口总是返回默认场次，而不是指定的那个。
- 用日历选日期的页面（例如 1084537866279，18 个场次），`performBases` 是空的，场次按月份放在 `dataDefault.calendarPerforms` 里。
- 有些演出电脑版不卖（按钮“该渠道不支持购票”，状态 100），这时 `performBases` 是空的，网页上也不展示场次和票档。
- 演出不存在时，详情页照样返回 HTTP 200，但页面里没有 `dataDefault`。
- `search.damai.cn/searchajax.html` 第一次匿名请求就返回滑块验证页（`_____tmd_____/punish`）。

## 考虑过的选项

1. **电脑版详情页 HTML + subpage 票档接口**：匿名可用，无需签名。代价：电脑版不卖的演出拿不到场次和票档；页面结构由大麦决定，可能变化。
2. **mtop H5 接口**（`mtop.damai.cn/h5/...`）：需要 `_m_h5_tk` token 和请求签名，实现和维护成本更高，也更容易触发风控。在只做查询时，没有比方案 1 多拿到需要的信息。
3. **在产品里跑无头浏览器**：最接近用户看到的页面，但又慢又重，和“高性能后端”的定位相反。浏览器只用于 agent 验证（computer use），不进产品。
4. **搜索接口**：第一次请求就触发风控，排除。

## 决定

采用方案 1，在 Rust 后端实现：

- HTTP 用 `reqwest`（rustls，系统信任库）+ `tokio`。后续抢票需要并发和低延迟，从第一天就用异步运行时，避免以后整体迁移。
- 场次的票档按顺序逐个请求，不并发，相邻两次请求间隔 300 毫秒：查询没有理由对大麦突发请求，而一场日历式演出可能有十几个场次。
- 状态只按观察到的取值映射（见 [subsystems/damai-event.md](../subsystems/damai-event.md)），没观察过的取值显示“未知”并附上原始值，不猜。
- 任何响应里出现风控页标记，就立即停止整个查询，不重试、不绕过。

## 后果

- 电脑版不卖的演出，只能告诉用户“电脑版不展示场次和票档”。要支持它们，需要另一个数据源（例如移动端），届时写一条新记录。
- 大麦改页面结构时，解析会失败并报出看得懂的错误；`backend/testdata/damai/` 里的真实响应能帮下一个 agent 对比新旧结构。
- 出现以下证据时应重新考虑：subpage 接口开始要求登录或签名；电脑版不卖的演出成为多数；风控开始拦截详情页。
