# 0011. 改版巡检：声明程序依赖的字段路径，拿真实响应和它比

- 状态：采用
- 日期：2026-10-14
- 相关：#10、#9（定时）、#17（登记定时任务）、#4（统一访问层）

## 背景

自动化测试只回放 `backend/testdata/damai/` 里录下来的响应，CI 绝不访问真实大麦（[0003](0003-tests-cannot-reach-damai.md)）。所以大麦一改版，程序就坏了，CI 却一直是绿的；最坏的情况是开售当天才发现解析失败。

[0001](0001-damai-event-data-source.md) 已经写了“大麦改版后，用 curl 匿名请求详情页和票档接口，和 testdata 里的旧响应对比结构”，但这一步只能靠人（或 agent）想起来去做，而且“对比结构”没有定义：两份 25 KB 的 HTML 用肉眼比不出区别。

另一半问题是状态码。程序只映射在大麦页面上核对过的取值，其他显示“未知（原始值）”。真实世界里新出现的状态码，在这之前没有任何渠道被发现。

约束：只读、不登录；所有 agent 共用 owner 家里一个出口 IP，#2 的盯票常常同时在跑；搜索接口第一次匿名请求就返回滑块页，不能用来找样本。

## 考虑过的选项

1. **逐字节对比整份响应**。实现最简单。代价：大麦每次请求都会换 `spm`、时间戳、促销文案，几乎每次都报“变了”，很快就没人看了。
2. **把整份响应变成结构快照（每个字段的路径和类型），和 fixture 的快照比**。能发现任何结构变化。代价：详情页有上千个字段，大麦改一个和程序无关的字段也会报警；而且快照文件要跟着 fixture 一起维护。
3. **只声明程序依赖的字段路径和它能读的 JSON 类型，拿真实响应和这份声明比**（选中）。报警范围正好是“程序会坏”的范围。代价：声明要和代码保持一致，否则会漏；靠守护测试把声明钉在真实 fixture 上。
4. **用 JSON Schema 之类的现成格式描述**。能用工具校验。代价：多一个依赖和一种语言，而且 schema 表达不了“这个字段数字和字符串都行，因为 `text::integer` 两种都接受”这种和读取代码绑定的约束。

样本来源的选项：搜索接口（第一次就被风控，排除）、把样本写死在仓库里（会过期，#10 明确要求能自动换）、从首页取（选中，首页匿名可用）。

开 issue 的方式：自己调 GitHub API（要存 token，违反凭据规则）、用已登录的 `gh` 命令（选中，凭据留在 owner 的机器上）。

## 决定

采用方案 3，在后端新增 `theflash::inspect` 模块和两条命令。

- **声明是单一事实来源**：[`shape.rs`](../../backend/src/inspect/shape.rs) 里每条 `Field` 写明路径、程序能读的 JSON 类型（`accepts`）、程序用它做什么（`used_for`），以及这个字段是不是必须有（`Need`）。`Need::OneOf` 表示“一组里至少要有一个”，因为场次在 `performBases` 或 `calendarPerforms` 两处之一。路径走进数组时，数组的元素本身也要声明（`perform.skuList[]` 是对象），否则元素变成 null 会把它下面的字段一声不响地全部带走；`every_array_a_path_descends_into_has_its_elements_declared` 守住这一条。
- **形状之外还要问语义**：票档接口会用完全正确的形状回答“这次查询失败了”（`responseInfo.responseSuccess` 是 `"false"`）或者回答另一个场次。这两种响应 `theflash event` 本来就当失败处理，所以巡检问的是同一个函数（`damai::tier_answer_problem`），不是另写一套判断——只比字段路径会把用户买不了票的响应报成“没有变化”。
- **声明由测试钉在真实数据上**：[`tests.rs`](../../backend/src/inspect/tests.rs) 用 `backend/testdata/damai/` 里的真实响应检查每条声明（类型都在 `accepts` 里、`Need::Always` 的字段处处都在、`Need::Optional` 必须有一份缺它的真实响应为证）。声明写错了，`make check` 就红，而不是等到巡检误报。
- **状态码只问映射表**：`damai::sale_state_of_code` 和 `damai::tier_code_is_mapped` 直接复用 `sale_state`/`tier_status`，所以“哪些码见过”只有一份定义，不会和显示逻辑漂移。
- **样本自动换新**：保存的样本不再是它那一类的状态时，从首页取候选，一个一个探，探到了就换，并把新样本集写回用户状态目录。不用搜索接口。**2026-10-14 实测发现真实首页的匿名 HTML 里没有演出链接（卡片是 JS 渲染的），所以这条路换不出样本**；候选从哪来改由 [0014](0014-inspection-sample-pool.md) 决定（候选池 + 按现在的状态重新归档 + 补不上就报警），首页退到最后一位。读首页的代码和它的真实 fixture 留着，`the_recorded_home_page_carries_no_detail_link` 钉住“今天没有链接”，大麦改回来时它会红。
- **换不出新样本是一个发现，不是一条说明**：某一类没有样本了，就没人在看那一类，所以退出码是 1，报告里单列“样本缺口”，issue 标题也写进去。这次读不了的旧样本留在样本文件里不删——一次请求失败不等于这场演出没了，删掉会让后面每一次巡检都少查一类，而且这件事发生在一次“成功”的运行里，没人会注意到。改了状态的那一场按新状态归档，这一类改由候选池兜底（[0014](0014-inspection-sample-pool.md)）。预算在轮到某一类之前就用完（`--max-events` 调小了）是另一回事，那是运行自己的选择，只写成说明。
- **节流和预算写进代码**：相邻请求默认至少 2 秒，一次最多 8 场。预算是上限不是目标：样本都有效时一次只读 5 页，剩下的 3 页是样本过期时换新用的额度——预算正好等于 5 的话，读完样本就没有余额去读候选，自动换新永远进不去。同一个 itemId 在样本集里出现两次只花一次额度。`--gap` 小于 2 秒只在请求发往本机回放地址（`127.0.0.0/8`、`::1`、`localhost`）时生效，判断的是请求去哪里，而不是“有没有设过覆盖地址”：设成真实大麦的覆盖地址同样要等满 2 秒。`inspect::request_gap` 和 `main::client` 读同一个值，不会一个以为是本地、另一个发给真实大麦。
- **开 issue 走 `gh`，接口可注入**：`tracker::Tracker` 是一个三个方法的接口，正式实现调用 `gh`，测试传入回放 `gh` 输出的实现。巡检自己开的 issue 正文里带一行标记，下一次有发现时在同一个 issue 上追加评论，不重复开。
- **录 fixture 的命令带脱敏**：`theflash inspect record` 把真实响应按规则脱敏后写进 `testdata/`，脱敏之后仍然命中规则的响应整份丢掉并说明原因（owner 的规则：出现凭据就整张删掉重录）。

怎么用、请求总数、怎么按 #17 登记定时运行，写在 [subsystems/damai-inspect.md](../subsystems/damai-inspect.md)。

## 后果

- 大麦改了程序依赖的字段或出现新状态码时，巡检会报出哪一场、哪个字段、原来是什么类型、程序用它做什么，并把脱敏后的候选 fixture 写到磁盘上供修复的 agent 使用。
- **候选 fixture 是大麦发的那份字节**，文件名就是 `testdata/damai/` 里的 fixture 名（`item_<itemId>.html`、`sku_<itemId>_<performId>.jsonp`），拷进去就能被现有的 `item_page_json` / `tier_json` 回放。读不懂的响应也留下来——那恰恰是修复的人最需要复现的那一份。候选文件在跑巡检的那台机器上，所以 issue 正文除了列路径，还写明怎么用 `theflash inspect record` 在别处重新取一份。
- 大麦改了程序不读的字段，巡检不说话。这是故意的：报警只覆盖“程序会坏”的范围。代价是新功能开始读一个新字段时，要在同一个改动里把它加进声明；`shape.rs` 的文档注释写了这条要求。
- 脱敏规则在 `inspect/redact.rs` 和 `backend/tests/repo_guard.rs` 里各有一份：后者是测试，不能被产品代码调用。两份都按 code-standards 的同一条规则写，`redact.rs` 的 `the_rules_find_what_the_repository_guard_finds` 用同样的样本盯住它们不漂移。把扫描逻辑提到库里、让 repo_guard 调用它，是更干净的做法，留给以后（#21 正在改 repo_guard，现在动会冲突）。
- 脱敏原本只管“写进仓库的 fixture”，报告和自动开的 issue 原样引用响应（#72）。现在同一份规则也管**巡检说出来的话**：`redact::for_report` 处理每一个从响应里抄出来的字符串。因此 `damai::sku` / `damai::page` 也要调 `inspect::redact`——这两条错误消息是用响应自己的字节拼的，而 `theflash event` 和巡检共用它们（#73）。模块名上这是反向依赖；规则是 owner 的、跨整个仓库的，模块放哪儿不是本次要解决的事，`redact` 该搬到库的顶层时一起搬。
- 这次用的是现有的 `damai::Client`，#4 的统一访问层当时还没合进 main。#4 合并后要做三件事：`inspect::stops_the_run` 换成 `Error::stops_damai_access`、`inspect::state_dir` 换成 `damai::state_dir`、巡检的 2 秒节流改成由 `Gate` 统一执行（巡检仍然要自己的 2 秒，因为 `Gate` 的下限是 300 毫秒）。
- 出现以下证据时应重新考虑：首页不再匿名返回演出链接（样本换新就要换来源）；大麦开始对详情页风控（巡检会第一个撞上）；声明的字段数长到没人维护（说明该换成从 fixture 自动生成快照）。
