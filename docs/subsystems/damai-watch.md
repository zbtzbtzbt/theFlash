# 盯票：开售提醒和回流提醒

> 按大麦时钟提醒开售、轮询回流

`theflash watch <链接或ID> [--session 场次] [--tier 票档] [--interval 秒] [--no-system-notify]` 盯住一场演出：未开售时按大麦的时钟倒计时，开售那一刻提醒，再确认是否真的能买；之后按间隔查询，盯的票档从没票变成可售时提醒。只读，不登录，不下单。为什么这样设计见 [0002](../decisions/0002-watch-timing-and-polling.md)；查询本身见 [damai-event.md](damai-event.md)。

## 运行路径

[`watch::run`](../../backend/src/watch/mod.rs) 只通过 [`Env`](../../backend/src/watch/env.rs) 和外界交互（单调时钟、睡眠、查询、读大麦时钟、输出）。生产环境用 `RealEnv`，测试用虚拟时间的 `Fake`（[tests.rs](../../backend/src/watch/tests.rs)）。

1. **开始**：查一次演出，只请求被盯场次的票档（[`Client::event_where`](../../backend/src/damai/client.rs)）。没有匹配的场次或票档时，列出可选项，退出码为 2。电脑版不卖的演出没法盯。
2. **未开售且有开售时间**：[`sale_open`](../../backend/src/watch/mod.rs)
   - 读大麦时钟：对详情页发 5 次 HEAD 请求（由 [大麦访问层](damai-access.md) 的频率上限隔开 300 毫秒），用响应头 `Date` 估计“大麦时间 − 本机单调时钟”（[`clock::estimate`](../../backend/src/watch/clock.rs)）。终端会显示大麦比本机快或慢多少，以及误差。
   - 倒计时：终端里每秒原地刷新；不是终端时每分钟输出一行。
   - 开售前每 10 分钟重查一次页面，开售时间变了就跟着改；开售前 20 秒再读一次时钟，这几次读数打开的连接到开售时还活着，开售后的第一次查询不用重新做 TLS 握手。
   - 每一轮都比较墙上时钟和单调时钟各走了多少；相差超过 2 秒（电脑睡眠过，macOS 的单调时钟睡眠时不走；或者时钟被调整），立即重新读大麦时钟。否则合盖睡一夜后，提醒会晚上睡眠的那么久。
   - 大麦时钟到达 `sellStartTime` 时提醒“开售时间到”，然后每秒确认一次（10 次后改为每 3 秒），直到盯的票档可售或页面变成在售，再提醒“已经可以买了”；开售后 60 秒仍不能买，就提醒“开售时间已过 1 分钟，还不能买”，然后转入回流轮询。
3. **已在售**：盯的票档里有可售的，立即提醒“现在就可以买”。
4. **回流轮询**：[`restock`](../../backend/src/watch/mod.rs) 每个间隔（默认 30 秒，最短 10 秒）查一次。票档从非可售变成可售时提醒“有票了”；从可售变回别的状态时输出一行“又没票了”，不发提醒。每 10 分钟输出一行“仍在盯：过去 10 分钟查了几次，都正常 / 失败几次”，长时间没有变化时，也能看出程序还在正常工作。

## 失败时的行为

| 情况 | 行为 |
| --- | --- |
| 风控页（任意一次查询或读时钟） | 提醒“触发风控，已停止盯票”，退出码 1；熔断写进用户状态目录，别的 theFlash 进程也停（[大麦访问层](damai-access.md)） |
| 别的 theFlash 进程（例如界面）触发了风控 | 下一次查询不发出，提醒“风控熔断生效，已停止盯票”，退出码 1 |
| 熔断状态文件损坏或状态目录不可写 | 提醒“读不到风控熔断状态，已停止盯票”，退出码 1 |
| 演出不存在 | 退出码 1 |
| 网络错误、HTTP 错误、看不懂的响应 | 输出原因，等待时间翻倍（30 → 60 → 120 → 240 → 300 秒封顶）后重试，恢复后回到正常间隔 |
| 某个场次的票档没查到 | 输出一行，其他场次照常 |
| 读不到大麦时钟（没有 `Date`） | 说明后按本机时钟倒计时，误差未知 |
| 几次时钟读数互相矛盾 | 只用最后一次，误差约半秒，并在终端说明 |
| 第一次查询就失败（例如断网时启动） | 直接退出并说明原因，不重试 |
| 本机没有 CA 证书，建不起 HTTP 客户端 | 启动时退出，退出码 1，提示和 `event` 相同（见[查询的失败行为](damai-event.md#失败时的行为)） |
| `THEFLASH_REQUEST_GAP_MS` 无效 | 启动时退出，退出码 1，不发请求，提示变量名和合法范围（见[查询的失败行为](damai-event.md#失败时的行为)） |
| Ctrl-C | 输出“已停止盯票”，退出码 0 |

## 提醒

终端：响铃字符加上 `【提醒】标题`，下面每行一条：演出名称、每个票档（场次 · 票档 · 价格 · 状态）、时间。开售相关的提醒用大麦时间（精确到毫秒），其他用本机时钟的北京时间。

系统通知：macOS 用 `osascript` 发到通知中心，Linux 用 `notify-send`。标题和正文作为参数传入，不拼进脚本（[`system_notification`](../../backend/src/watch/notify.rs)）。命令不存在时说明一次，之后只在终端提醒。`--no-system-notify` 关掉系统通知。

手机通知：可配置 ntfy，标题与桌面相同，正文在 4096 字节以内时逐字相同。较长正文保留演出、开头完整票档、时间和开售确认状态，并说明省略票档数量；终端和桌面仍保留完整正文。没有配置时行为不变；失败只说明一次投递的固定原因，继续盯票，下一次状态变化照常投递。后台发送不等待第三方服务，`--no-system-notify` 不关闭手机推送。配置、权限和投递限制见 [手机提醒](phone-push.md)。

## 请求量

启动时输出“每 N 秒查一次，每次 M 个请求（约 X 个/小时）”，M = 1（详情页）+ 被盯的场次数。默认间隔下，只盯一个场次大约每小时 240 个请求。开售确认最多 60 秒，每次 M 个请求。

同一个进程里，所有请求之间至少隔 300 毫秒（[大麦访问层](damai-access.md)），所以一轮 M 个请求至少要 (M−1)×0.3 秒。跨进程不共用这个上限：同时开着界面和盯票时，大麦看到的是两边相加的流量，理由见 [0005](../decisions/0005-damai-access-gate.md)。

## 验证

- `make check`。虚拟时间的测试在 [`watch/tests.rs`](../../backend/src/watch/tests.rs)：开售提醒按大麦时钟而不是本机时钟、确认重试、一分钟内不能买的提醒、回流每次只提醒一次、断网退避后继续、风控停止、开售时间改动、读不到时钟时的退路。假环境查询超过 1000 次或虚拟时间超过 30 天就判失败，所以一个本该停下却没停的改动会让测试失败，而不是卡住。
- [`tests/watch.rs`](../../backend/tests/watch.rs) 运行编译出的程序：参数、过滤、只请求被盯的场次、Ctrl-C、风控，以及用假服务器的 `Date` 头验证倒计时按大麦时间而不是本机时间。
